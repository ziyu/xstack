## Overview

This project is a monorepo with two main apps:

- CLI: `apps/cli`
- Documentation site: `apps/web`

## Setup

### Prerequisites

- Node.js (lts)
- Bun (recommended)
- Git

### Install

```bash
git clone https://github.com/ziyu/xstack.git
cd xstack
bun install
```

## Develop the CLI

```bash
cd apps/cli
# optional global link for testing anywhere
bun link
# run in watch mode (runs tsdown build in watch mode)
bun dev
```

Now go to anywhere else in your system (maybe like a test folder) and run:

```bash
xstack
```

This will run the locally installed CLI.

## Develop the Website and Template Builder

From the repository root:

```bash
bun install
bun run build:cli
bun run --filter @xstack/backend dev
```

Keep the backend running. Local Convex does not require a cloud account. Set `NEXT_PUBLIC_CONVEX_URL` in `apps/web/.env.local` to the client URL printed by Convex, normally `http://127.0.0.1:3210`.

In `packages/backend`, configure the statistics component's token without placing it in shell history:

```bash
gh auth token | bunx --no-install convex env set GITHUB_ACCESS_TOKEN
bunx --no-install convex env set GITHUB_WEBHOOK_SECRET
```

The first command reuses an authenticated GitHub CLI account for local development. The second prompts for a separate webhook signing secret. Do not commit credentials or the local `.convex/` database. Start the website in another terminal with `bun dev:web` from the repository root; open `/new` to use the Template Builder.

Builder presets, provider controls and previews share the generator module catalog. Keep URL state, command generation and preview conversion aligned. Logos are local SVG files in `apps/web/public/icons/`, rendered by the shared `TechIcon` component with CSS-selected theme variants.

## Contribution Flow

1. Open an issue/discussion before starting major work
2. Fork the repository
3. Create a feature branch
4. Make changes following existing code style
5. Update docs as needed
6. Test and format

```bash
# From the repository root
bun run build:cli
bun test apps/cli/test packages/template-generator/test
bun run --filter web check-types

# Builder preview and generated-command regressions
(cd apps/web && bun test test)

# Lint + format checks
bun check
```

7. Commit and push

```bash
git add .
git commit -m "feat(web): ..." # or fix(cli): ...
git push origin <your-branch>
```

8. Open a Pull Request and link any related issues

## Commit Conventions

Use conventional commit messages with the appropriate scope:

- `feat(cli): add new CLI feature`
- `fix(cli): fix CLI bug`
- `feat(web): add new web feature`
- `fix(web): fix web bug`
- `chore(web): update dependencies`
- `docs: update documentation`
